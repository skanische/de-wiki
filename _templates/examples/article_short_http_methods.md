# HTTP Methods

## 1. Кратко

- HTTP method показывает намерение клиента при обращении к ресурсу.
- В REST API методы часто используются для операций над сущностями.
- Самые частые методы: `GET`, `POST`, `PUT`, `PATCH`, `DELETE`.
- `GET` обычно используется для чтения данных.
- `POST` часто используется для создания ресурса или запуска операции.
- `PUT` обычно означает полную замену ресурса.
- `PATCH` обычно означает частичное изменение ресурса.
- `DELETE` используется для удаления ресурса.


## 2. Где используется

HTTP methods используются при интеграции с API.

Для Data Engineer эта тема важна в задачах:

- загрузка данных из REST API;
- построение ingestion jobs;
- работа с пагинацией;
- отправка статусов во внешние системы;
- запуск внешних API-операций;
- интеграция Airflow/Python jobs с внешними сервисами;
- диагностика ошибок API.

Пример DE-сценария:

Data Engineer пишет ingestion job, который забирает события из внешнего API. Для чтения данных используется `GET`, для обновления статуса обработки может использоваться `POST`, `PUT` или `PATCH` — в зависимости от контракта API.


## 3. Как работает

HTTP request обычно состоит из:

- method;
- URL;
- headers;
- query parameters;
- body;
- response status code;
- response body.

Основные методы:

| Метод | Типичное назначение |
|---|---|
| GET | Получить ресурс или список ресурсов |
| POST | Создать ресурс или выполнить операцию |
| PUT | Полностью заменить ресурс |
| PATCH | Частично обновить ресурс |
| DELETE | Удалить ресурс |

Пример соответствия REST-операций:

| Операция | Метод | Пример endpoint |
|---|---|---|
| Получить пользователя | GET | `/users/123` |
| Создать пользователя | POST | `/users` |
| Полностью заменить пользователя | PUT | `/users/123` |
| Частично обновить пользователя | PATCH | `/users/123` |
| Удалить пользователя | DELETE | `/users/123` |

Важная идея:

HTTP method сам по себе не гарантирует поведение API. Реальное поведение определяется контрактом конкретного сервиса. Но в хорошо спроектированном REST API методы обычно используются по общепринятой семантике.


## 4. Примеры

### GET

Получение данных:

```
GET /users/123
```

Пример на Python:

```python
import requests

response = requests.get(
    "https://api.example.com/users/123",
    headers={"Authorization": "Bearer <token>"},
    timeout=30,
)

response.raise_for_status()
data = response.json()
```

### POST

Создание ресурса:

```
POST /users

{
  "name": "Ivan",
  "status": "active"
}
```

Пример на Python:

```python
import requests

payload = {
    "name": "Ivan",
    "status": "active",
}

response = requests.post(
    "https://api.example.com/users",
    json=payload,
    headers={"Authorization": "Bearer <token>"},
    timeout=30,
)

response.raise_for_status()
created_user = response.json()
```

### PUT

Полная замена ресурса:

```
PUT /users/123

{
  "name": "Ivan",
  "status": "inactive"
}
```

### PATCH

Частичное обновление ресурса:

```
PATCH /users/123

{
  "status": "inactive"
}
```

### DELETE

Удаление ресурса:

```
DELETE /users/123
```


## 5. Частые ошибки и диагностика

### Частые ошибки

1. Путать `PUT` и `PATCH`.

`PUT` обычно означает полную замену ресурса.  
`PATCH` обычно означает частичное изменение.

2. Использовать `GET` для операции, которая меняет состояние.

Для изменения состояния лучше использовать `POST`, `PUT`, `PATCH` или `DELETE`.

3. Считать, что `POST` всегда только создает ресурс.

На практике `POST` часто используют и для запуска операций: например, пересчитать отчет, отправить задачу, инициировать экспорт.

4. Не читать контракт конкретного API.

Разные API могут использовать методы неидеально или нестандартно. Опираться нужно на документацию конкретного сервиса.

5. Не обрабатывать ошибки HTTP.

Недостаточно просто вызвать API. Нужно проверять status code, обрабатывать retryable errors, timeouts и rate limits.

### Диагностика

Что проверять при ошибках:

- HTTP status code;
- response body;
- request URL;
- query parameters;
- headers;
- authorization token;
- request body;
- timeout;
- rate limits;
- pagination parameters.

Типовые коды:

| Код | Значение |
|---:|---|
| 200 | Успешный запрос |
| 201 | Ресурс создан |
| 204 | Успешно, но body нет |
| 400 | Ошибка запроса |
| 401 | Нет авторизации |
| 403 | Нет прав |
| 404 | Ресурс не найден |
| 409 | Конфликт состояния |
| 429 | Слишком много запросов |
| 500 | Ошибка сервера |
| 502/503/504 | Временные проблемы сервиса или gateway |
